# 03 — UX

## 1. Shell

- **Navigation**: left `NavigationRail` with sections, replacing the prototype's top tabs.
  Labels (final): **Home**, **Profiles**, **Versions**, **Addons**, **Macros**, **Settings**.
  - "Versions" = installed/downloadable FreeCAD builds (user-facing name for *build*).
  - Bundles live under Addons as a second tab ("Catalog" / "Collections"); they also appear
    in the profile context ("Apply collection").
- **Status bar** at the bottom: active jobs (progress + label), update badge, warnings
  (offline, FUSE/Gatekeeper), app version.
- **App bar**: section title + contextual actions (search, refresh, check updates).
- **Theme**: Material 3, seeded color scheme, dark default, light toggle persisted.
- **Inputs**: desktop density, prototype-style forms — labeled fields put the label in a fixed
  left column (130 px, `Label:` with optional icon, 12 px gap, 12 px between rows) using the
  shared `FormRow`/`FormTextField`/`FormDropdown` widgets; the input itself is a compact fully
  outlined field with 4 px corners defined once in the app `InputDecorationThemeData`. Search
  fields and filter rows stay compact and unlabeled.
- **Window**: minimum size 900×600; all critical flows usable without horizontal scrolling.

## 2. Screens

### 2.1 Home

- First-run state: a short 3-step checklist (Add a FreeCAD version → Create a profile →
  Install addons), plus a "Guided setup" button.
- Normal state: a **Recent profiles** row at the top — up to five compact cards in last-launch
  order (name, build label/channel, last-used time, running badge; the whole card launches, a
  chevron opens the profile detail; profiles whose build is missing/broken are hidden); then the
  status tiles (versions/profiles/addons/macros/packages), the "Updates available" summary and
  the news feed (D-067, D-104).
- Empty/error states for each card with a single clear action.

### 2.2 Versions (builds)

- Tabs: **Installed** | **Available** | **Custom**.
  - Installed: cards/rows with display label (user label or version), channel badge
    (`stable`/`weekly`/`custom`), arch, size, Python version, status, used-by count, actions
    (Rename, Update, Verify, Delete, Show in folder). Renaming opens a dialog pre-filled with
    the current label; clearing it restores the version label (D-069).
  - Available: channel filter **Stable | Weekly** (Stable default) for the detected OS/arch.
    Stable lists releases with date/size/checksum indicator and an "Install" button; Weekly
    lists at most the latest 52 dated `weekly-YYYY.MM.DD` development builds (one year, newest
    first) with a badge and an install confirmation warning (never auto-installed, D-077). The
    legacy channel appears here in v0.2 (B-01).
  - Custom: add local file / URL / existing executable (self-compiled or installed by other
    means, referenced in place; local AppImages symlinked, not copied) with trust confirmation,
    version label, optional checksum; after import, unknown Python offers a "choose Python
    executable" fallback or skip.
- Install dialog: size, available disk, target dir, extracted size estimate, progress with
  cancel and explicit stage feedback (hashing / downloading / installing / detecting Python)
  plus transferred bytes and speed while downloading; checksum failure shows expected/actual.
  After a successful install or custom import the view switches to the **Installed** tab;
  failures stay on the current tab.
- Build detail drawer: release notes link, asset name, SHA-256, install path, profiles using it.

### 2.3 Profiles

- Grid/list of profile cards: name, FreeCAD version + channel, addon count, Python package
  count, size on disk, last used, health; actions Launch, Open folder, Duplicate, Export, Delete.
  Duplicate asks for the new name and whether to copy config only or the full payload (D-028).
- Profile detail page with tabs:
  - **Overview**: paths, env preview, launch button, "Show launch command", config files.
  - **Addons**: installed list with update badges, add/remove/update, pin/unpin (pinned addons
    show a Pinned chip and never an update badge), enable/disable switch (writes/removes the
    `ADDON_DISABLED` marker; disabled rows show a Disabled badge and a dimmed title), apply
    collection.
  - **Python**: installed packages, install (spec or requirements paste), logs.
  - **Macros**: list, install from catalog, reveal/open/delete.
  - **Config**: config file status, backup/restore, reset (v0.2), preference browser (v0.2).
  - **Backups**: export manifest/full, import target list, restore config snapshots.
- Create/profile edit dialog: name, build picker (grouped stable/weekly, incompatible Python
  versions flagged), optional base template.

### 2.4 Addons

- **Catalog** tab: search field (text and `#tag`), filters (content type, FreeCAD range,
  installed state, tag), virtualized grid of addon cards (icon, name, short description,
  tags, installed badge). Content and installed-state filters are multi-select in a checkable
  menu (filter button with an active-filter count badge).
- Addon detail page: description, authors/roles, license, repo link, version, FreeCAD range,
  branches (with radio selection), last update, install target profile picker, install/update/
  remove buttons, dependency summary. When the selected profile has the addon pinned, a Pinned
  chip replaces the update badge and Update is disabled until the addon is unpinned.
- **Collections** tab: bundle list, create/edit, apply, export/import, item editor with catalog
  search.
- **Custom** tab (v0.2): a shared install-target profile picker, then three forms — repository
  URL + branch/ref (with the resolved archive URL preview), a local archive file picker and a
  local directory link (with the live-link warning) — plus a list of custom-installed addons
  with Update (repository), Reinstall from file (archive), Open source folder (dev link),
  **Install in another profile…** (target-profile picker; profiles that already have the addon
  are not offered) and Remove actions. Ids already installed in the profile are blocked with a
  "remove first" error.

### 2.5 Macros

- List of macros across a selected profile (profile switcher in the app bar) with name,
  size, modified date.
- Catalog and installed lists show the macro's catalog icon when one is available (PNG/SVG;
  XPM and iconless macros fall back to a generic icon), served from a local icon cache.
- Actions: install from catalog, delete, reveal in folder, open with default editor.
- v0.2: "Run in FreeCADCmd" with output panel.

### 2.6 Settings

- General: theme, data directory (read-only display + reveal; move is v0.2), update cadence,
  CLI wrapper (path, installed/PATH status, install/remove).
- Network: GitHub token (masked, test button), proxy note (system proxy respected).
- Cache: catalog cache, downloads cache, per-item size, clear buttons.
- Logs: folder, level, open, export debug bundle.
- About: version, license (GPL-3.0-or-later), third-party notices, links.

## 3. Core flows

### 3.1 First run

```
Launch app
  └─ no installed builds, no profiles
       ├─ [Guided setup]
       │    1. detect OS/arch + diagnostics (FUSE/Gatekeeper/disk)
       │    2. choose a FreeCAD release (latest stable preselected)
       │    3. download + verify + install (progress, cancellable)
       │    4. name the profile (default "Default")
       │    5. optionally pick addons from a short recommended list
       │    6. launch FreeCAD
       └─ [Skip] → Home empty state
```

### 3.2 Install build

```
Versions → Available → Install
  ├─ preflight: disk space, connectivity, FUSE (Linux)
  ├─ download with progress + cancel
  ├─ verify SHA-256 (fail → clear error, delete .part)
  ├─ extract (AppImage: single file; 7z/dmg: extract to builds/<id>/)
  ├─ detect bundled Python version (run <python> -c ...)
  └─ DB commit → toast "Installed 1.1.3" → appears in Installed + pickers
```

### 3.3 Create profile and launch

```
Profiles → New
  ├─ name + build picker (Python-version warning on mismatch)
  ├─ create dirs: profile/, profile/home/, profile/Mod/,
  │               profile/AdditionalPythonPackages/, profile/temp/
  ├─ write nothing into user.cfg (FreeCAD creates it on first run)
  └─ Launch → spawn with isolated env → running indicator while alive
```

### 3.4 Addon install with requirements

```
Catalog → addon → Install into <profile>
  ├─ resolve branch (default first compatible)
  ├─ download zip → safe-extract to temp
  ├─ if requirements.txt found:
  │     dialog: "This addon needs N Python packages" + list
  │       ├─ [Install packages then addon]  → pip job (log visible)
  │       ├─ [Install addon only]           → warn imports may fail
  │       └─ [Cancel]
  ├─ move temp → profile/Mod/<AddonId> (backup old on update)
  └─ DB commit + toast with "View in profile"
```

### 3.5 Apply collection

```
Profile → Addons → Apply collection → pick bundle
  ├─ preview table: item | installed | action (install/update/skip/conflict)
  ├─ confirm → sequential jobs with aggregate progress
  └─ summary: N installed, M updated, K skipped, E failed (retry failed)
```

### 3.6 Update check

```
[Check updates] (or scheduled)
  ├─ builds: GitHub releases (ETag-cached) → badge on Versions
  ├─ addons: catalog vs installed per profile → badges on profiles/addons
  │    (pinned addons are skipped per profile; other profiles still badge)
  └─ launcher: own releases (v0.2) → banner
Each badge opens a summary sheet; "Update all" confirms a batch with per-item toggles.
```

### 3.7 Export / import

```
Profile → Backups → Export
  ├─ Manifest (JSON)  ← default, portable, small
  └─ Full archive (zip) [v0.2] with toggles: config / macros / addon payloads
Import → pick file → preview (name clash → "(imported)") → create → optional reinstall
```

## 4. Interaction rules

- **Consent**: any flow that downloads executables or runs third-party install code shows a
  summary (source URL, size, checksum status, packages) and requires an explicit confirm.
- **Destructive actions** (delete build/profile/addon/macro, clear cache) always confirm and
  state exactly what is removed; profile delete offers "export first".
- **Long operations** are cancellable, show progress, and never block navigation.
- **Errors** are inline where the action happened, include a short cause + a "Details" expander
  with the raw log tail, and a retry when safe.
- **Offline** shows a persistent status-bar chip; install/update actions are disabled with a
  tooltip, browsing uses cache.
- **Launch transparency**: every launch offers "Copy launch command" showing env + argv.
- **Keyboard**: `Ctrl/Cmd+1..6` switch sections, `Ctrl/Cmd+N` new profile, `F5` refresh,
  `Ctrl/Cmd+F` search, `Esc` closes dialogs/drawers.

## 5. State coverage checklist

Every list screen must define: loading, empty, filtered-empty, error, offline, and
partial-data states. Every job must define: queued, running, paused/cancelled, failed,
completed. Every profile must define: healthy, build-missing, build-broken, migrating.
